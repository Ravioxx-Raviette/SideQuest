# Cart Undo Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans here and obtain a final read-only review.

**Goal:** Recover accidental bag removals with their original quantities.
**Architecture:** cart-undo.js holds a session-memory removal stack and renders an inline bag recovery region. Existing confirmed removal records a snapshot before mutation; existing bag rendering refreshes the strip. Checkout routing and cross-tab cart updates invalidate history.
**Tech Stack:** Existing HTML/CSS/JavaScript and Playwright.
**Spec:** docs/superpowers/specs/2026-11-13-cart-undo-design.md.

## Global Constraints
- Keep confirmation and existing cart storage/99-unit rules.
- No timed expiry, whole-cart rollback, or overwriting newer cart changes.
- Saved restoration must respect storage-failure feedback.
- Accessible focus, empty-bag recovery, mobile support; no dependencies.

## Review Focus
- Multiple removals must restore quantities/order correctly.
- Re-added quantities must merge without exceeding 99 or losing history.
- Checkout and cross-tab invalidation must prevent stale restores.
- Empty checkout redirects must preserve recovery.
- Storage failures and dismissed controls must not lose feedback or focus.
